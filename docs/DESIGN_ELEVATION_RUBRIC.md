# SZL Design Elevation Rubric

## Purpose

The elevation kit improves clarity, craftsmanship, accessibility, and developer/investor usability. It does not authorize claim inflation, visual homogenization, or copied brand expression.

## Scorecard

| Dimension | Required outcome |
|---|---|
| Identity | A visitor can name the artifact class and job in under ten seconds |
| Truth | Status is explicit, textual, accessible, and evidence-bound |
| Navigation | Canonical source is the primary action; mirrors, successors, and references are subordinate |
| Developer path | A valid install, use, verify, or unavailable path is visible without searching |
| Investor path | Value, maturity, evidence, and limitation are visible in the first screen |
| Craft | Semantic tokens, consistent spacing, responsive hierarchy, and deliberate typography |
| Accessibility | Keyboard, focus, contrast, semantic heading, non-color state cue, reduced-motion behavior |
| Integrity | No fictional charts, weights, benchmark results, deployment posture, or authority claims |

## Artifact-specific elevation

| Artifact | Elevation priority |
|---|---|
| Active model | Base model, intended use, eval posture, artifact identity, quickstart, limitations |
| Kernel | Not-a-model marker, API/import, evidence/test state, source/mirror relation, limitations |
| Dataset | Schema, provenance, data restrictions, splits, consumer relation, citation/license |
| Space | Product/runtime posture, source repo, real capability boundary, fallback state, help path |
| GitHub repo | Job, architecture position, install/verify, canonicality, Hub/Space relation, contribution posture |
| Archive | Historical purpose, explicit successor or terminal-evidence reason, no active call to action |

## Prohibited shortcuts

- One generic card copy-pasted across unrelated artifact classes.
- Hero imagery substituted for missing evidence.
- Decorative status treatment that hides BLOCKED, UNAVAILABLE, ARCHIVED, or EXPERIMENTAL states.
- A redesign that changes source, license, evidence, or runtime claims without source-level audit.
- Any duplicate canonical card, route, or active mirror.
