# David Leads — Federal Refresh Snapshots

Immutable, hash-chained snapshots of normalized public federal records serving the David Leads Space. Produced by the `federal-refresh` workflow in `szl-holdings/david-leads` (issues #103; PRs #104, #105, #106).

## Layout

- `snapshots/YYYY-MM-DD/snapshot.json` — snapshot metadata (sha256 of upstream bytes, records_hash, created_at, freshness_days)
- `snapshots/YYYY-MM-DD/receipt.json` — PurIQ v1 receipt (a11oy #1814); `UNSIGNED` is honestly labeled until a signing key is configured
- `snapshots/YYYY-MM-DD/records.jsonl` — normalized source records, one JSON object per line
- `latest.json` — pointer to the current snapshot

## Verification

Every snapshot passes six checks before publish and again at consumption: per-record content-hash recomputation, `records_hash` chain, receipt `payload_hash`, signed-receipt key_id presence, gate-must-be-pass, and staleness window. Verifier: `tools/ingestor/verify_snapshot.py`.

## Estate law

Snapshots are immutable (dated paths never overwritten). No sample substitution. No live-web calls by consumers. Stale data renders honestly: "data as of {date}, refresh pending."

### Sources

Started with EPA ECHO Exporter (weekly). Follow-on lanes: FMCSA MOTUS, DOL Form 5500 bulk, USAspending.
